# 关键机制

（本文按当前 `src.zip` 源码核对更新）

本文说明目标页面识别、悬浮窗显示与隐藏、页面/包名切换、答题解禁、休闲时刻、提醒文字、持久化及服务清理之间的关系。

## 1. 总体架构

  ```text
  无障碍窗口事件 / 2 秒轮询
      ↓
  AppStateManager 识别前台包名、目标页面与解禁状态
      ↓
  FloatService 将状态变化转为窗口操作
      ↓
  FloatingWindowManager 创建、暂停、恢复或移除悬浮窗
      ↓
  MathChallengeManager / LeisureTimeManager 处理解禁
  ```

  [`FloatService`](../app/src/main/java/com/book/mask/floating/FloatService.java) 是协调入口；[`AppStateManager`](../app/src/main/java/com/book/mask/floating/AppStateManager.java) 负责包名、关键词与定时器；[`FloatingWindowManager`](../app/src/main/java/com/book/mask/floating/FloatingWindowManager.java) 负责窗口资源和暂停状态。

  ## 2. 权限与服务启动

  应用依赖：

  - 悬浮窗权限：创建 `TYPE_APPLICATION_OVERLAY`。
  - 无障碍服务：读取前台包名和活动窗口节点。

  [`MainActivity`](../app/src/main/java/com/book/mask/ui/MainActivity.java) 自动按“悬浮窗 → 无障碍”顺序引导；每项权限在一次 Activity 启动内最多自动跳转一次，状态会随实例状态保存，避免拒绝后反复拉回设置页。

  业务入口是系统连接 `FloatService` 后执行 `onServiceConnected()`。当前动态配置仅监听：

  - `TYPE_WINDOW_STATE_CHANGED`
  - `TYPE_WINDOW_CONTENT_CHANGED`

  并设置 `FLAG_INCLUDE_NOT_IMPORTANT_VIEWS`。XML 声明 `canRetrieveWindowContent=true`。当前源码**没有**监听 `TYPE_VIEW_CLICKED`，也没有启用 `FLAG_REPORT_VIEW_IDS`；控件点击学习方案尚未合入。

  ## 3. 目标应用与页面识别

  ### 3.1 包名识别

  前台包名来源：

  1. 窗口状态事件：及时响应切换。
  2. 每 2 秒读取活动根窗口：补偿漏报。

  两条路径最终都进入 `handleObservedPackage()`。处理前过滤：

  - 本应用包名。
  - 已登记输入法、部分常见输入法，以及包名含 `input` 的应用。

  窗口事件的包名只代表“哪个窗口发生了状态变化”，不代表“哪个应用在前台”：后台窗口（典型如桌面被全屏遮挡后滞后数百毫秒才结算的 stop）同样会带着自己的包名上报。因此当窗口事件可能触发“离开目标应用”时，`resolveForegroundPackage()` 会先读活动窗口根包名校正（进入方向不校验，以免拖慢悬浮窗抢先显示）：

  - 活动窗口不明确：沿用事件包名，宁可误判也不漏判离开。
  - 活动窗口仍是当前目标应用：判为后台窗口事件并丢弃，另安排一次 300ms 兜底复核，纠正活动窗口偶尔滞后于真实切换的情况。
  - 活动窗口是其他包名：以活动窗口为准。

  2 秒轮询本就读活动根窗口，不受此校正影响。

  包名只有同时满足以下条件才是受支持应用：

  - 属于预置应用或自定义应用。
  - 该应用监测开关已开启。

  预置应用与自定义应用由 [`CustomAppManager`](../app/src/main/java/com/book/mask/config/CustomAppManager.java) 管理。

  ### 3.2 页面关键词识别

  进入受支持应用后，服务递归遍历活动窗口节点：

  - 优先读取 `text`，为空时读取 `contentDescription`。
  - 只有命中节点 `isVisibleToUser()` 时才算有效。
  - 实际匹配方向为：

  ```java
  targetWord.contains(nodeText)
  ```

  例如配置为 `推荐 精选 热点`，独立节点“推荐”可命中；若节点文字比配置字符串更长，则可能不命中。

  微信是特例：只要当前包名为微信，即使根节点为空，也直接判为目标页面，因此实际效果是屏蔽整个微信。

  ### 3.3 防抖与暂停边界

  内容变化事件采用：

  - 停止变化 200ms 后检测。
  - 连续变化最多等待 500ms，达到上限即执行一次。

  不同暂停机制的范围不同：

  - 包名切换复核：暂停页面检测，并忽略中间包名事件。
  - 休闲时刻：暂停绑定应用的页面关键词检测，但包名切换仍可继续处理。
  - 答题界面：暂停页面关键词检测；窗口状态事件与 2 秒前台包名轮询继续运行，以便离开目标 APP 时及时隐藏悬浮窗。自身窗口和输入法包名会被过滤。
  - 悬浮窗显示防抖：窗口由隐藏变为显示后，仅暂停包名事件与轮询 500ms；不直接暂停内容检测。结束后主动复核活动根窗口包名。

  ### 3.4 进入应用时的显示顺序

  默认采用“先显示、后检测”：确认进入目标包名后先请求显示悬浮窗，再延迟检测页面关键词，避免节点遍历阻塞首帧。

  - 普通应用默认延迟 100ms。
  - 抖音使用可配置的首次检测延迟。

  每个应用会记录上次离开前的最后一次关键词结果。只有同时满足以下条件，才标记为“下次先检测、后显示”：

  - 最后一次检测未命中关键词。
  - 当前不在该应用的休闲时刻内。
  - 当前没有手动解禁隐藏。

  再次进入该应用时：

  - 已标记：先扫描，命中后再显示。
  - 未标记：先显示，再扫描。

  新一轮进入会清除该应用上一次“缺少关键词”结果，避免旧页面状态继续影响本轮。

  ## 4. 悬浮窗显示

  `showFloatingWindow()` 的核心顺序：

  1. 当前应用处于休闲时刻时跳过。
  2. 尝试恢复页面/包名切换保留的暖窗口。
  3. 已有正常挂载窗口时跳过重复创建。
  4. inflate `floating_window_layout.xml`。
  5. 创建答题管理器并绑定关闭按钮。
  6. 读取提醒文字、目标日期和解禁时长。
  7. `WindowManager.addView()`。
  8. 成功后启动 500ms 包名检测防抖。
  9. 后台预取下一次提醒文字。

  窗口默认参数：

  - `FLAG_NOT_FOCUSABLE`
  - `FLAG_NOT_TOUCH_MODAL`
  - `FLAG_WATCH_OUTSIDE_TOUCH`

  横向覆盖全屏，纵向范围按应用独立配置：

  ```text
  窗口高度 = 屏幕高度 - 顶部偏移 - 底部偏移
  ```

  ## 5. 两类隐藏

  ### 5.1 正式隐藏

  调用 `WindowManager.removeView()`，并释放 View、答题管理器和暂停状态。下次显示需重新 inflate 和 `addView()`。

  主要场景：

  - 答题成功或休闲时刻关闭。
  - 确认离开目标应用且不保留暖窗口。
  - 暖窗口保留期到期。
  - 服务销毁或管理器清理。

  ### 5.2 暂停隐藏（暖窗口）

  短暂切换时优先执行：

  ```text
  layoutParams.alpha = 0
  layoutParams.flags |= FLAG_NOT_TOUCHABLE
  WindowManager.updateViewLayout(...)
  ```

  失败时回退为 `View.INVISIBLE`。恢复时还原透明度、Flags 或 `View.VISIBLE`。

  暖窗口可以跨目标应用复用。复用到另一目标应用前，会在仍不可见时原地更新：

  - 上下偏移和窗口高度。
  - 提醒文字与解禁时长。
  - 答题上下文，包括微信特例。

  `layoutParams` 被答题控制器持有，只能原地改写，不能替换对象。

  暖窗口期间 `isFloatingWindowVisible` 与 `Share.isFloatingWindowVisible` 仍为 `true`；它们表示“窗口仍挂载并受管理”，不表示肉眼可见或可触摸。

  ### 5.3 暂停原因叠加

  [`WindowSuspensionState`](../app/src/main/java/com/book/mask/floating/WindowSuspensionState.java) 维护：

  - `PAGE_TRANSITION`
  - `SYSTEM_UI`

  第一个原因出现时才物理隐藏，最后一个原因解除时才恢复，避免状态重叠时提前显示。
## 6. 页面与应用切换

  ### 6.1 同一应用内离开目标页面

  关键词由命中变为未命中时，窗口进入 `PAGE_TRANSITION` 暂停并保留 1.5 秒：

  - 保留期内重新命中：恢复原窗口。
  - 超时仍未返回：正式移除。

  ### 6.2 离开目标应用

  当观察到其他包名、当前仍有挂载窗口且未处于 SystemUI 暂停时：

  1. 记录原应用下次进入的显示顺序。
  2. 清除当前应用状态，但保留原窗口应用信息。
  3. 将窗口降级为透明、不可触摸的暖窗口。
  4. 进入包名切换复核，忽略中间包名事件和页面检测。
  5. 300ms 后读取活动根窗口包名。

  首次复核：

  - 仍是原目标包名：再暂停 `1000 - 300 + 100 = 800ms`，随后复核一次。
  - 不是原目标包名：立即结束复核，按当前包名恢复常规处理。

  结束复核后：

  - 原目标应用：重新确认进入并恢复暖窗口。
  - 另一目标应用：跨应用适配并复用暖窗口。
  - 非目标应用：保持隐藏，暖窗口在保留期到期后释放。
  - 包名为空：等待后续事件或轮询。

  包名切换暖窗口默认最长保留 2 秒。若窗口此前已因页面切换暂停，可能仍受原 1.5 秒保留任务约束。

  若检测到系统“过渡动画缩放”为 0，则跳过 300ms 复核，直接确认离开并正式隐藏。

  ### 6.3 SystemUI

  观察到 `com.android.systemui` 时：

  1. 先保持遮罩 100ms。
  2. 复核已回目标应用：不暂停或恢复。
  3. 复核仍是 SystemUI：将窗口暂停为透明且不可触摸。
  4. 复核为其他包名：按普通包名切换处理。
  5. 包名为空、本应用或输入法：150ms 后重试。

  ## 7. 答题与普通解禁

  点击关闭按钮的优先级：

  1. 微信已开启“答题解锁”：显示答题界面。
  2. 已预备休闲时刻：免答题关闭。
  3. 微信未开启“答题解锁”：直接按答题成功处理。
  4. 其他应用：显示答题界面。

  [`ChallengeViewController`](../app/src/main/java/com/book/mask/challenge/ChallengeViewController.java) 通过 `ViewStub` 在首次答题时懒加载答题布局，而不是在普通悬浮窗创建时加载。答题界面会：

  - 隐藏顶部提醒区域。
  - 将窗口 Flags 改为仅 `FLAG_NOT_TOUCH_MODAL`，使输入框可获焦点。
  - 延迟显示键盘并周期性维持输入焦点。
  - 根据键盘可见区域调整题目高度。

  答错后显示 1 秒反馈，再生成同类型下一题；答对后显示 1 秒反馈，再执行关闭。

  普通解禁流程：

  1. 宽松模式时增加当日关闭次数。
  2. 读取本次解禁时长。
  3. 持久化关闭时间与本次时长。
  4. 在 `Share` 标记手动隐藏。
  5. 正式移除窗口。
  6. 启动该应用的内存定时器。
  7. 到期清除手动隐藏。
  8. 若仍在该应用，强制检测页面并按结果显示。

  时长：

  | 模式 | 可选时长            | 次数规则             |
  | ---- | ------------------- | -------------------- |
  | 严格 | 30、60、120 秒      | 不增加宽松次数       |
  | 宽松 | 10、15、20、30 分钟 | 每次关闭增加当日次数 |

  宽松解禁定时器到期后，会把该应用当前时长切换为最长严格时长 120 秒。

  ## 8. 休闲时刻

  休闲时刻与单应用严格/宽松解禁是两套机制。

  用户在设置页开启休闲时刻时，只进入待触发状态：

  - 不开始计时。
  - 不消耗次数。
  - 不绑定应用。

  首个点击关闭悬浮窗的应用会激活：

  1. 将模式绑定到该应用包名。
  2. 持久化结束时间。
  3. 消耗一次该模式的当日次数。
  4. 同时记录一次该应用关闭时间，并增加应用宽松关闭计数。
  5. 标记手动隐藏并正式移除窗口。
  6. 清理待执行的内容检测、SystemUI 确认和包名切换任务。
  7. 有效期内跳过该应用页面检测和窗口显示。
  8. 到期后强制复查当前页面。

  严格休闲与宽松休闲分别持久化时长、次数、已用次数、结束时间和绑定包名。普通解禁定时器到期时，如同一应用仍处休闲时刻，会顺延到休闲结束。

  ## 9. 题目机制

  题型包括：

  - 算术题
  - 混合题
  - 推理题
  - 英文阅读题

  英文阅读当前由 `QuestionConst.ENGLISH_READING_ENABLED=false` 禁用；历史配置若选择英文阅读，会回退为混合题。

  推理题和英文阅读题使用进程内远程题缓存：

  - 有缓存：立即使用，同时异步请求下一题。
  - 无缓存或请求失败：回退本地算术题。

  因此远程请求通常不阻塞当前答题界面。

  ## 10. 提醒文字与 Provider

  当前支持：

  - 官方云端 Provider。
  - OpenAI 兼容自定义 Provider。

  Provider 配置和 API 密钥由独立模块管理；自定义 Provider 设置开关当前开启。

  普通悬浮窗展示路径：

  1. 按当前 Provider、目标和风格读取本地缓存。
  2. 无缓存时展示默认提醒。
  3. 窗口显示后异步预取。
  4. 正常预取完成只写缓存，不替换当前窗口；下次创建或暖窗口更新时读取。

  用户修改目标、风格或 Provider 后是另一条路径：

  1. 取消旧请求。
  2. 当前窗口先显示“加载中，请稍等”。
  3. 请求完成或失败后清除等待态。
  4. 立即刷新当前窗口为新缓存或兜底文字。
  5. 再预取下一次文字。

  ## 11. 持久化与运行时边界

  持久化数据不只位于一个 MMKV：

  - 通用设置：`SettingsStorage` 对应 MMKV。
  - 自定义应用与预置应用修改：独立 MMKV。
  - 输入法、包名日志、提醒缓存、Provider 配置：各自独立存储。
  - 自定义 Provider API 密钥：Android Keystore 加密后写入独立 `AtomicFile`，不是明文 MMKV。

  主要持久化内容：

  - 应用列表、监测开关、关键词、窗口偏移、文字来源。
  - 解禁时长、关闭时间、宽松次数。
  - 休闲时刻配置、次数、结束时间、绑定包名。
  - 题型、算术难度、目标、提醒风格。
  - Provider 配置、提醒缓存。

  主要内存状态：

  - `Share.currentApp`、页面状态、手动隐藏标记。
  - 每应用最后关键词结果与下次进入策略。
  - 窗口挂载/暂停状态。
  - 页面检测、包名复核和恢复定时器。
  - 远程题缓存。

  服务销毁后，普通关闭时间仍在磁盘，但手动隐藏标记与 Handler 定时器不会自动恢复；因此进程重建后可能在原解禁期限内重新显示遮罩。休闲时刻因结束时间和绑定包名均已持久化，可继续按剩余时间判断。

  ## 12. 保活与清理

  [`ServiceKeepAliveManager`](../app/src/main/java/com/book/mask/lifecycle/ServiceKeepAliveManager.java) 当前执行：

  - 动态注册亮屏、息屏、用户解锁和开机完成广播。
  - 用户解锁后复查窗口/页面状态。
  - 每 30 秒检查一次 `FloatService` 静态实例。

  这不是强保活：

  - 无障碍服务由 Android 系统管理，代码不能自行重新开启。
  - 动态开机广播只有进程已运行且接收器已注册时才可能收到。
  - Manifest 中未声明独立开机接收器或前台服务。

  `FloatService.onDestroy()` 会：

  - 清除应用恢复定时器和检测任务。
  - 移除悬浮窗与答题界面。
  - 注销动态广播。
  - 关闭 `DeviceInfoReporter` 的执行器。
  - 取消提醒文字的在途请求，但 `ReminderTextRepository` 是单例，其执行器本身不会在这里关闭。
  - 清空 `Share` 运行时应用状态。
